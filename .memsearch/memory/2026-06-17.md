- User asked whether a workflow YAML file can block direct pushes to the master branch instead of using repo settings.
- Claude Code explained that workflow YAML files cannot block pushes because GitHub Actions workflows run after a push is already accepted by Git; the push decision happens at the Git-protocol level.
- Claude Code clarified that blocking direct pushes requires branch protection rules (or rulesets) configured in repo settings, not in the workflow file.
- Claude Code identified three code-based alternatives to the Settings UI: `gh ruleset create` (GitHub CLI), Terraform's `github_branch_protection` resource, or GitHub's REST API directly.
- Claude Code emphasized that the workflow file and branch protection rules are independent pieces: the workflow defines what to run, while the protection rule decides whether the workflow result blocks pushing/merging.
